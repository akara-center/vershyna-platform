# Серверна Вершина 2.0

## Перевірка на комп’ютері

Потрібен Node.js 24. З каталогу репозиторію виконай:

```sh
node server/start.cjs provision test-coach coach
node server/start.cjs provision test-client client
node server/start.cjs
```

Команда створення акаунта один раз виводить ключ. Передай його власнику приватним каналом. У тестах використовуй вигадані дані. Відкрий [локальний акаунт](http://127.0.0.1:8787/account). Ключ клієнта відкриває трекер, ключ коуча відкриває кабінет. Щоб перевірити автоматичне збереження, увійди тим самим клієнтським ключем у двох незалежних профілях браузера.

- Зміни надсилаються після короткої паузи. Відкрита вкладка отримує серверну версію приблизно раз на п’ять секунд. Якщо відкритий редактор або є незбережений текст, оновлення зачекає.
- При втраті мережі чернетка лишається в цьому браузері. Після відновлення мережі застосунок повторює запис. При різних версіях можна завантажити свою чернетку й вибрати версію. Заміна потребує підтвердження та зберігає датовану копію в «Дані».
- Для перенесення вже наявного прогресу з GitHub Pages експортуй JSON у пілоті та імпортуй його в акаунті або в трекері. Після першого імпорту зміни синхронізуються автоматично.
- Втрачений ключ замінює адміністратор командою `node server/start.cjs rotate-key ID_АКАУНТА`. Попередній ключ і всі сесії цього акаунта відкликаються.

## Розгортання

Хостинг має запускати один постійний процес Node.js 24 або Docker-контейнер, надавати HTTPS і постійний диск для SQLite. GitHub Pages лишається статичним пілотом на вигаданих даних.

| Налаштування | Значення |
| --- | --- |
| Команда запуску | `node server/start.cjs` |
| Зовнішня адреса | `VERSHYNA_ORIGIN=https://твій-домен` |
| Порт | `VERSHYNA_PORT`, стандартний `PORT` або 8787 |
| Інтерфейс | `VERSHYNA_HOST=0.0.0.0` для контейнера або 127.0.0.1 за локальним HTTPS-проксі |
| База | `VERSHYNA_DB` — файл на постійному диску |
| Перевірка сервісу | `GET /healthz` |
| Календар | `VERSHYNA_GOOGLE_CLIENT_ID`, `VERSHYNA_GOOGLE_CLIENT_SECRET`, `VERSHYNA_GOOGLE_TOKEN_KEY` |

Для Docker зберігай каталог `/data` у постійному томі з правом запису для користувача контейнера. Для безпечного резервування створюй новий файл через `node server/start.cjs backup шлях-до-нової-копії.sqlite`. Ця команда копіює узгоджений стан бази. Тримай копію в захищеному сховищі. Для відновлення зупини процес, збережи окремо поточну базу, розмісти копію за шляхом `VERSHYNA_DB` і запусти ту саму версію. Для збережених календарних підключень потрібен той самий ключ шифрування токенів.

Після старту перевір `/healthz`, вхід клієнта й коуча, синхронізацію двох сесій, приватну гілку, відкликання доступу, резервну копію та відновлення. Для Google додатково налаштуй OAuth і перевір реальну подію в обох напрямках за [інструкцією календаря](CALENDAR.md). Перед роботою з реальними даними перевір шлях резервування й відновлення саме на обраному хостингу.

## Railway Free

Підключи GitHub-репозиторій `akara-center/vershyna-platform`, гілку `main`, з коренем збірки в корені репозиторію. Railway підхопить `Dockerfile`. Залиш стандартну команду запуску контейнера й додай healthcheck `/healthz`.

1. Приєднай до сервісу Volume з точкою монтування `/data`. Контейнер використовує `/data/vershyna.sqlite`. Без тому сервер на Railway завершує запуск із повідомленням про помилку. Каталог налаштовується під час запуску, після чого сервер переходить на користувача `node`.
2. У Public Networking згенеруй HTTPS-домен. Сервер бере адресу з `RAILWAY_PUBLIC_DOMAIN`. Якщо використовується інша зовнішня адреса, явно задай `VERSHYNA_ORIGIN` і виконай redeploy. Сервер слухає порт `PORT`, який передає Railway.
3. Після успішного запуску перевір `/healthz` і `/account`. Створюй окремі акаунти в контейнері, наприклад `railway ssh /bin/sh /app/server/container-start.sh node /app/server/start.cjs provision ID_АКАУНТА client`. Для коуча роль `coach`. Тримай видані ключі поза GitHub, журналами деплою та публічними каналами. Для заміни ключа використай `rotate-key ID_АКАУНТА` тією самою командою.
4. Налаштуй резервне копіювання тому. Перевір збереження даних після redeploy і відновлення копії на синтетичних даних до відкриття сервісу клієнтам.

Ліміт Free — 0,5 ГБ постійного диска і $1 кредиту на місяць. Коли кредит вичерпано, сервіс зупиняється до нового розрахункового періоду або зміни тарифу. Умови та відмінності пробного періоду описані в [Railway Free](https://docs.railway.com/pricing/free-plan).

## Автоматичні перевірки

`node scripts/check-syntax.cjs` перевіряє синтаксис. `node --test tests/*.test.cjs` запускає тести браузерної логіки, HTTP API, контрактів, видимості й Google Calendar на підставних відповідях. GitHub Actions запускає окремий браузерний сценарій через Playwright для клієнта у двох профілях і кабінету коуча. Він використовує чисту базу в пам’яті.
