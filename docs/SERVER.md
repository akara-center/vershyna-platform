# Серверна копія Вершини 2.0

Для локального тесту з каталогу репозиторію потрібен Node.js 24. Виконай:

```sh
node server/start.cjs provision test-client
node server/start.cjs
```

Перша команда створює тестовий акаунт і один раз показує випадковий ключ доступу. Друга запускає локальний сервер. Відкрий http://127.0.0.1:8787/account і увійди ключем. Копію JSON можна взяти з «Дані» в трекері. Сервер зберігає одну поточну копію на акаунт із номером версії. На іншому пристрої з доступом до того самого запущеного сервера можна увійти в цей акаунт і завантажити копію для імпорту в трекер. Локально порт доступний тільки на комп’ютері, де працює сервер.

Ключі доступу й токени сесій представлені в базі хешами. Браузер отримує окремий сесійний cookie, який стає Secure з HTTPS-адресою. Це тестовий спосіб входу. Відновлення доступу, ролі клієнта й коуча, підключення Google та автоматична синхронізація лишаються наступними частинами. Для будь-яких тестів до завершення цього етапу використовувати вигадані дані.

## Перенесення

GitHub тримає код і тести. GitHub Pages публікує `dist/`. Код сервера запускається командою `node server/start.cjs` на комп’ютері або Node.js-хостингу. Сервер слухає loopback, для зовнішнього доступу налаштовується HTTPS-проксі. `VERSHYNA_ORIGIN` задає зовнішню адресу HTTPS, `VERSHYNA_PORT` — локальний порт, `VERSHYNA_DB` — шлях до бази на постійному диску. Для перенесення зупини процес, перенеси SQLite-файл з постійного диска та запусти ту саму версію з новою адресою. Якщо тестова база була тимчасовою, створи нові тестові акаунти. Базу, ключі й резервні копії не додавай у GitHub.
