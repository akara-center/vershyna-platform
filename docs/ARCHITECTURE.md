# Карта розвитку Вершини

Актуально: 22.11.2026, структурний етап. Вихідний код — dist/, публікація без збірки.

## Файли

| Файл | Відповідальність |
|---|---|
| `dist/state.js` | Спільний стан, селектори місії, localStorage, датовані копії, початкова нормалізація |
| `dist/templates.js` | 21 чиста функція HTML/SVG; явні параметри, точне об’єднання фрагментів |
| `dist/ui.js` | Діалоги, тап зовні, меню, повідомлення, святкування, копіювання тексту |
| `dist/timer.js` | Таймер поточної сторінки, запуск/пауза/скидання |
| `dist/tasks.js` | Виконання, скасування, фокус, зміни проєктів, архів і видалення |
| `dist/render.js` | Відображення вкладок, проєкту, задач, прогресу, героя й нагород |
| `dist/editors.js` | Форми кроку, серії, проєкту й перенесення, перевірка введення |
| `dist/data.js` | JSON-імпорт/експорт, копії, екрани архіву/кошика, запит для ChatGPT |
| `dist/app.js` | Прив’язка подій та запуск після завантаження всіх частин |

QuestCore у quest-core.js зберігає бізнес-правила дерева й XP. initial.js — порожній стан та сумісність старих форматів. index.html — статичний каркас і послідовність підключень; styles.css — вигляд.

## Завантаження й залежності

index.html підключає quest-core → initial → state → templates → ui → timer → tasks → render → editors → data → app, звичайними script без async/defer. Файли ділять поточну глобальну область видимості; це організація за відповідальністю, не ізоляція ES modules. Залежності доступні до виконання app.js; до того визначаються функції та змінні, збереження не запускається.

app.js викликає initializeState(), bindModalBackdrop(), налаштовує глобальні події, дату, render(). state.js залежить від QuestCore/migrateState й показує помилки через toast під час операцій. tasks.js викликає save/render/resetTimer. render.js готує дані для Templates і викликає bind(). editors.js та data.js відкривають modal, перевіряють введення й передають зміни стану. timer.js оновлює час і викликає render/toast при завершенні. UI-функції користуються спільними DOM-помічниками зі state.js.

Templates — чисті функції рядків з явними параметрами. Вони не читають localStorage чи DOM. Викликач має екранувати користувацький текст через esc; не передавати сирі name/result/goal в HTML. Фрагменти об’єднуються join(""), щоб зберегти пробіли тексту й textarea. Не форматувати HTML літерали додаванням відступів без перевірки результату.

2. Для нового файла додати відносний script у правильному порядку до app.js. Ніяких платних чи runtime-залежностей для цієї архітектури не потрібно.

4. Пройти наявні Node-тести; для UI — браузерне порівняння за BASELINE.md. Тести VM використовують tests/helpers/app-source.cjs і фактичний порядок index.html.

Перехід на ES modules або збирач можливий окремо, коли для цього буде практична потреба. Поточна структура зберігає просту статичну публікацію й наявні інтеграційні тести.

## Розширення 2.0

`pilot-core.js` визначає модель бачення, оцінок, журналу виконання та текст звіту. Функції форматування й обліку не читають DOM або сховище. `pilot-ui.js` — навігація і форми. `pilot.css` — стилі нових екранів. `demo.js` — окрема синтетична місія. Новий блок зберігається в одному JSON разом із деревом трекера через `state.js`. Сховище — локальний браузерний адаптер, серверного адаптера поки немає. `docs/DATA.md` описує сумісність і часові правила.
