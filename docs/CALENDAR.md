# Google Calendar

У пілоті: «Мій день» → меню «⋯» біля задачі → «Додати в Google Calendar». Вказати час і тривалість, підготувати подію, відкрити Google Calendar і зберегти подію. В Google передаються тільки назва вибраної задачі та часовий інтервал. Форму можна перевірити без підключення акаунта. Разова подія не пов’язана із задачею після створення.

## Погоджена двостороння синхронізація

Зв’язок тільки для вибраних задач. Спільні поля: назва, початок і кінець робочого слота. Планова дата й дедлайн задачі, виконання та XP лишаються окремими. Підтверджене скасування Google-події очищає слот, зберігаючи задачу. При подвійній правці одного поля або конфлікті інтервалу потрібен вибір. Помилка доступу не є видаленням. Події без точного часу й повторювані події поза підтримкою першої версії.

`server/calendar-sync.cjs` — модуль Calendar API й алгоритму обміну для окремого зв’язку. Три версії для порівняння: остання узгоджена, поточний слот у трекері, поточна подія. Незалежні зміни об’єднуються. Умовний запис за ETag повертає результат для повтору, коли Google-подію встигли змінити. Модуль ізольований від браузерної збірки. Тести застосовують підставну відповідь Google, без реальних акаунтів.

У серверній версії увійди в акаунт, відкрий «Мій акаунт» → «Google Calendar» і підтвердь доступ. Прив’язку робочого слота ввімкни окремо для вибраної задачі в її меню. Синхронізація перевіряє прив’язані події на сервері щохвилини, доки працює сервер. При конфлікті меню задачі показує обидва варіанти. При від’єднанні події лишаються у Google Calendar.

## Налаштування на хостингу

1. У Google Cloud увімкни Calendar API, налаштуй екран згоди й створи OAuth-клієнт типу Web application.
2. Додай адресу перенаправлення `https://твій-домен/api/calendar/callback`. Вона має збігатися з `VERSHYNA_ORIGIN` та шляхом callback.
3. У секрети хостингу внеси `VERSHYNA_GOOGLE_CLIENT_ID`, `VERSHYNA_GOOGLE_CLIENT_SECRET` і `VERSHYNA_GOOGLE_TOKEN_KEY`. Ключ шифрування можна створити командою `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"`.
4. Для тестового OAuth додай тестовий Google-акаунт, увійди у Вершину, прив’яжи тестову задачу. Перевір зміну назви й часу, конфлікт, скасування події та від’єднання. Перед відкритим запуском перевір, які вимоги Google застосовує до публікації та перевірки цього OAuth-клієнта.

Сервер запитує доступ до власних подій базового Google-акаунта. Раніше синхронізовані слоти звіряються за версіями. Для скасувань сервер зберігає маркер інкрементальної видачі та підтвердження лише щодо власних прив’язок. Саму задачу, її дедлайн і XP скасування Google-події зберігає. Ознайомчий тест використовує підставні відповіді Google.
